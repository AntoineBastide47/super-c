# Native backend

## Native backend

A native build compiles each module's LIR to a machine object in place of its C units.

| File | Content |
|------|---------|
| `src/codegen/live.spc` | The analysis pass (TPDE): block layout in reverse postorder with each loop contiguous, a loop's cold blocks after its warm ones and the other cold blocks last, loop nesting, each value's live range and use count. A cold block that branches into a block before it runs inside the ranges live there: each value live at its target lives to the cold block's position and is kept (`cold_entries`). `ranges` records next uses over the folded operand lists; `advance` updates the cursors during emission. Both register backends prefer an eviction that needs no store, then the farthest next use. `plan`: which values hold a register for their whole range or an initial block prefix, by a linear scan in range order where a value of more weight (use frequency, 8 per loop level) takes the register of the lightest active one. A displaced interval can retain its prefix before a block boundary no backward edge crosses (`cut`, `splits`, `home_at`); every edge into its suffix for a block that reads the value writes a reserved stack home (`save_splits`). Shared homes, aggregate entry pointers and shrink-wrapped functions do not split. The generators ask per value (`want`: a callee-saved register for a value a call runs in the range of, either kind for one that lives past its block). `folds` (arm64 and x86-64, `fold_max`): a load or store at a single-use `ptradd` with an index, no offset and a scale of 1 or the access's size addresses through the base and index registers (`ldr x0, [x1, x2, lsl #3]`, `(%rax,%rcx,8)`; on arm64 a slot's address at offset 0 is sp itself, and a `ptradd` of a frame address and a scaled index is one `add` of an extended register, no copy of sp); the `ptradd` emits nothing (`pfold`) and `uses_at` moves its operands' uses to the access. `fold_ops` (the target's `FOLD_*`) folds more: a compare into its selects and branches, an `and` compared with 0 (`tst`), a product into a sum (`madd`), a shift into a mask (`ubfx`), the two shifts of a rotation with its amount's extensions (one both amounts read too), `and`, `sub` or `neg`, which the generator reads past (`rot_amount`) (`rotate_of`: by `k` and `w - k`, by `s` and `w - s`, and for an `or` by `s` and `-s & (w - 1)`, a masked `s` of 0 being no rotation of an `xor` or a sum), and a sum's shifted index and inner sum (`lea_of`, one `lea`). A folded instruction emits nothing; each of its uses computes it, and an operand of a folded instruction lives to that use. `back_param`: the parameter a back edge passes a value to, whose register the generators define that value in (`def_step`, `step_reg`), so the edge moves nothing; a branch's other edge must leave the loop, and when the parameter lives past the loop no path from that exit may read it before the header (`reads_before`, at most `BACK_SCAN` blocks, those past the range's end skipped); `reduces`: a vector reduction, which calls nothing |

| `src/target/a64gen.spc` | One code generation pass per body: the homes `Live::plan` gives (x19..x28 and v8..v15; x9..x15 and v16..v29 for values no call runs in the range of), temporaries in the others, stack slots for the rest, far-branch retry. Vectors of 8 or 16 bytes live in v registers, their slot written (`sync`) before an instruction whose code may branch past a lane (a masked access) reads it there; a 16-byte vector that lives past its block, crosses no call and only lane-wise operations with a Neon form, loads, stores and edges use (`vec_homes`) takes a caller-saved v register home. `def_step`: a one-instruction result a back edge passes to a parameter is defined in the parameter's register; one that outlives the loop (a rotated loop's exit reads it) takes the register over as its home when the parameter's range ends in its block. Two loads or stores at adjacent offsets through one address value pair into one `ldp` or `stp` in either offset order (`pair_next`, `pair`). The search crosses at most seven pure scalar instructions, never memory or control flow. The second load is defined early and may take its planned fixed home; a second store source must already exist. An already assigned second load home prevents pairing; an aggregate argument at a frame address loads its two 8-byte parts with one `ldp` through sp or fp (`frame_addr`). A register-passed aggregate parameter read only by entry-block loads of whole parts, before any instruction that may call, gives those loads its registers and takes no memory (`parts_taken`, `taken`; x64gen too). A product by 2^s + 1 is `add x, x, x, lsl s`, by 2^s - 1 a shift and a subtraction; a rotation (`lv::FOLD_ROT`) is `ror` (EXTR) by a constant or `rorv`, a left one by the negated amount; one of 8 or 16 bits (`rotate_narrow`) is the zero-extended value shifted both ways and joined by a constant, or by a register a 32-bit `rorv` of the register filled with the value's copies (their period divides 32); a high product of 32 bits or fewer takes `umull` or `smull` of the operands' W registers; a zero extension of a `clean` value reuses its register; a select's integer 0 is `xzr`, and its result takes the back-edge register (`def_step`). A `splat` is one `dup`. Homes: a leaf (no call but to a path that does not return, no system operation, variadic access or thread-local address) has 10 scratch homes from x0..x15 (`leaf`, `XSCR_LEAF`), not 6 from x9..x15, an entry parameter keeping its arrival register (`take_home` `prefer`); an entry parameter that dies in the entry block keeps its register too. A loop header's parameter and the value its back edge passes share one register or slot (`back_share`, `shared`, `is_shared`; `edge_moves` skips a move to itself); a value spilled without a home takes the stack slot of the loop parameter it steps when it is that parameter's one reader (`step_slot`, `Live::slot_partner`), and the one of the two that ends last frees it, and a forward jump's argument is defined in its target parameter's register (`def_fwd`). An extern function's call under `no_plt` on ELF is `adrp/ldr/blr x16` through its GOT slot. For ELF (`Gen.elf`): TLS descriptors, a shared object's global symbols through the GOT, each frame's `.eh_frame` rules; for Mach-O its compact unwind encoding. Callee-saved registers are saved in whole pairs (x19/x20 to x27/x28, d8/d9 to d14/d15), each pair below the last with its lower register 8 bytes higher, the layout compact unwind's frame mode states; under the standard convention a variadic body saves x0..x7 and q0..q7 for its `va_list`. An unsigned or equality comparison with a constant whose negation modulo the width is below 4096 is `cmn` of that negation (`x != 0xFFFFFFFF` is `cmn w, #1`) |

`driver::emit` sets `Package.native` for every linking build; a linking build for a target `nat::supported`
does not name fails ("no native backend for ..."), and an emission alone (`--emit-c`) writes C.
`native_header_facts` reads the constants of the
scoped C headers with the own preprocessor (in parallel, cached in `__sc_hfacts` by file size and
mtime; its first line names its format) under `--sysroot` or the discovered one, and the scalar class
of each `@layout` opaque type through its typedefs (`Package.opaque_cls`, `bindgen::scalar_class`).
Lowering gives such a type that LIR scalar type, not an aggregate: Microsoft x64 passes a one-field
struct of a `double` in an integer register, the `double` itself in xmm. A typedef of a struct or union
of scalars is `bindgen::SC_REC`: `bindgen::c_layout` computes its size, alignment and leaves from the
header's members (`Package.opaque_lay`), and lowering takes those leaves when the size and alignment
equal the declared `@layout` (a bitfield, a vector member, a `packed` or `aligned` attribute or a
`#pragma pack` leaves it unknown). Without a C environment for the target (no sysroot) a header has no
facts: its functions are the library's exports. The calling conventions classify an aggregate by its
layout leaves (scalars at offsets; an enum's tag and a capture by reference are leaves). A layout of 1
to 64 bytes whose leaves are unknown keeps none (`abi::unknown_class`), so the LIR stays complete; the
System V and AAPCS64 generators refuse a body whose signature or call passes one
(`CallLayout.unknown`), and the build fails with the refusal. Microsoft x64 passes an aggregate by its size alone. A dyn table a body's
lowering demands while it holds the lowering lowers when that body ends (`CEmit.dyn_due`). Float
arithmetic on two constants folds (`lir::eval::float_op`, also the interpreter's rule): a NaN result is
the first NaN operand quieted, else the positive quiet NaN, as LLVM folds it, since wasm leaves a new
NaN's sign to the host. A shared-library build sets `Package.pic`: x86-64 code then reaches every
global symbol through the GOT. A call moves its scalar register arguments, and a vector one register
takes whole, in one parallel move from where they are; a vector result one register returns stays
there. Windows thread-locals are native TLS (`.tls$`, SECREL), as clang and gcc 16 emit them.

An intrinsic with a row in its instruction set's table (`intrin::find`) is a plain LIR call; the
backend puts its arguments where its template expects them (`abi::intrinsic_layout`: vectors and floats
in v0/xmm0 and on, integers in x0.. or rdi, rsi, rdx, rcx, r8, r9, r10, r11, the result in v0/xmm0 or
x0/rax; on wasm the operand stack, through locals when the template reads its arguments in another
order) and expands the template in place of the call, its constant arguments substituted (a
non-constant one where the template needs an immediate refuses the body). The expansion clobbers what a
call does; on Windows the values in rdi and rsi, which Microsoft x64 saves, go to slots around it.
`native_header_facts` reads the headers under the target's sysroot (`Package.sysroot`, from
`--sysroot=`, else discovered by `bindgen::ctarget`).

A module the backend cannot compile (module-level assembly the target's assembler does not take, a
body the lowering or the backend refuses, a call of a header's `static` function or of an intrinsic
without a template) is a build error that names the module and why (`native_plan`); `SC_NATIVE_STATS`
reports each module. Each native module gives `m.o` (its own items, reused by the emission cache) and
`m__inst.o` (the rest). The record `__sc_native` holds, per module, the key its own part was compiled
under (its emission cache key xor `nat_base`, which mixes in the build configuration, the CPU
features, the LIR optimizer's switches, the header facts and, with debug information, the compile
directory), its low bit `NAT_OBJ`
when that part has an object; `nat_trust` turns an emission cache hit into a miss when the record does
not hold the module under the current key.

Debug information follows the profile's `debug` key (`loader::Package.debug_info`), which sets
`lir::ir::Package.debug` and its `comp_dir` (the compiler's working directory). Each
generator records a row per change of LIR location at the instruction's code offset (x86-64 maps them
through jump relaxation), the prologue taking the first row's location; `codegen::dwarf` writes them.
The code and data sections are the same bytes with and without it (`tests/codegen/debug_info_test.spc`).

A native build renders no C body (`cemit::backends_of`: no `BK_C` for any module; `emit_body_core`
returns at once); the declarations still render, and so does every body of the vector backend entries'
emitter (`CEmit.render_all`: a header's `static inline` C, no object's). Where a body renders no C, its
lowering journals for the TU cache what it demands (`rec_on` stays on: statics through `lir_stat_need`,
type descriptors through `CEmit::ti_need`), which the renderer journals otherwise. The registry is a
native object too (`__sc_registry_n.o`); `__sc_registry.c` is still written, and no C compiles it.
The vector bounds-check helpers live in `std/rt/lanes.spc`, loaded only when a
program names a vector type.

`check_all` (in `lir_stage`, under `SC_LIR`) verifies every body the build lowered (the
per-TU cache keys on `SC_LIR`, so a replayed module passed it before), and under `SC_LIR_EVAL` in a
test build runs each test without fixture arguments in the evaluator, the tests spread over
`--jobs` workers with an evaluator each: against the CTFE run (`lw::probe_tests`, before the body
syntax is released, 1<<18 steps; trap kind and location must match), or, where CTFE stops at a
construct it does not support, against the test's expectation (it passes, or with `should_panic` it
traps). A test that calls FFI (CTFE's `Interp.ffi`, or the evaluator's `EV_FFI`) or passes a budget
(CTFE's, or the evaluator's 1<<21 steps) is not compared. The test build then ends: `run_package`
returns after the emission, and `manifest_test` builds no project binary and runs no test.
