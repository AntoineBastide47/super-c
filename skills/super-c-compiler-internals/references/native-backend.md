# Native backend

## Native backend

A native build compiles each module's LIR to a machine object in place of its C units.

| File | Content |
|------|---------|
| `src/codegen/live.spc` | The analysis pass (TPDE): block layout in reverse postorder with each loop contiguous, a loop's cold blocks after its warm ones and the other cold blocks last, loop nesting, each value's live range and use count. A block the layout puts after a block it branches to (a cold block, or one the layout left for later) runs inside the ranges live there: each value live at its target lives to that block's position and is kept (`rare_entries`). `ranges` records next uses over the folded operand lists; `advance` updates the cursors during emission. Both register backends prefer an eviction that needs no store, then the farthest next use. `assign`: the register plan. Each value the generator asks a register for (`want`) takes a specific one per block where it is live, the heaviest first (the frequencies of its definition's and uses' blocks, `frequencies`: a static estimate propagated in reverse postorder, a branch split evenly but a rare successor's share 1 in 16, a loop header 8 times its entering edges, an edge out of a loop 8 times less per loop left). Liveness is exact: per value the blocks it is live in (`spread`, a backward walk from its reads) and in each the positions from its definition to its last read (`ends`), so two values live at no common position hold one register: a block parameter that of the argument an edge passes it, a result that of its first operand when that ends there (`over`, `over_inst`; any operand of a `three_op` on a target that sets `three`, limited to the operands `two_op` allows on one that sets `two`), which the planner prefers (`hints`, `pick`), and no move is made; a block parameter is placed no later than the step that replaces it (`kw`: with no call between them, any value its block's edge passes to the parameter that nothing in that block reads the parameter after; across a call, one that may write over it), a callee-saved register the body does not save yet costs `SAVE_COST`, none when the generator saves it together with one the body saves (`Sets.pair`), and a load of a part of an aggregate received in registers stays in the register it arrives in (`part_in`). A class holds a value only where nothing writes its registers while the value lives (`calm`, from the generator's call tables `cfirst`, `clast`, `wfirst`, `wlast`) and the block has room (`addable`: `Caps`, `scap`, `jcap`). A value no register holds everywhere takes the one that gains most over a part of its blocks (`spans`: the loads saved against the edges that enter, a load on one of several edges weighing `EDGE_BLOCK` times; no span a late edge enters) and keeps a stack home, written once where it is defined (`seg_mem`); or it takes the register of a holder that is idle in its blocks, which then keeps a stack home itself (`evict`); or a caller-saved register over all of its blocks, which each call it lives across saves around itself, when those saves cost less than a stack home (`past_put`, `seg_past`, from the generator's `ccount` and `wcount`). In a body that sets its frame up in the blocks of `after` alone, a callee-saved register holds a value in those blocks only (a fresh one costs two runs of the frame's edges, `save`), and a value made outside them keeps a register everywhere: the one saved around the calls, or one outside those blocks and another in them, with a move on each edge between the two (`frame_put`). The plan is one segment per value (two after that split: `vseg`, `vnext`) with its register (`seg_r`), `sin` (per layout position the segments that hold their value there, `seg_of`) `bmask` (per layout position the plan's registers in that block) and `solo` (those of them one value alone holds there and no edge out writes: a temporary may take one after its value ends). No partial segment for a constant a generator rebuilds (`WANT_WHOLE`), a flag or an aggregate's pointer. The generators ask per value (`want`: both classes for a value that lives past its block or across a call; a callee-saved register alone for a flag). `folds` (arm64 and x86-64, `fold_max`): a load or store at a single-use `ptradd` with an index, no offset and a scale of 1 or the access's size addresses through the base and index registers (`ldr x0, [x1, x2, lsl #3]`, `(%rax,%rcx,8)`; on arm64 a slot's address at offset 0 is sp itself, and a `ptradd` of a frame address and a scaled index is one `add` of an extended register, no copy of sp); the `ptradd` emits nothing (`pfold`) and `uses_at` moves its operands' uses to the access. `fold_ops` (the target's `FOLD_*`) folds more: a compare into its selects and branches, an `and` compared with 0 (`tst`), a product into a sum (`madd`), a shift into a mask (`ubfx`), the two shifts of a rotation with its amount's extensions (one both amounts read too), `and`, `sub` or `neg`, which the generator reads past (`rot_amount`) (`rotate_of`: by `k` and `w - k`, by `s` and `w - s`, and for an `or` by `s` and `-s & (w - 1)`, a masked `s` of 0 being no rotation of an `xor` or a sum), and a sum's shifted index and inner sum (`lea_of`, one `lea`). A folded instruction emits nothing; each of its uses computes it, and an operand of a folded instruction lives to that use. `back_param`: the parameter a back edge passes a value to, whose register the generators define that value in (`def_step`, `step_reg`), so the edge moves nothing; a branch's other edge must leave the loop, and when the parameter lives past the loop no path from that exit may read it before the header (`reads_before`, at most `BACK_SCAN` blocks, those past the range's end skipped); `reduces`: a vector reduction, which calls nothing `views` (`FOLD_VIEW`, last of the folds): a conversion that keeps its operand's bits (a truncation, a pointer/integer cast, a pointer's copy, a zero extension of a load or of a zero extension) is a view of its operand: it has that value's index and no range of its own, and each read of it is a read of that value (`seen`, `arg`), so the two never take two registers (code-generator.md, Views). |

| `src/target/a64gen.spc` | One code generation pass per body: the registers `Live::assign` plans (x19..x28 and v8..v15; x9..x15 and v16..v29 where no call runs while the value lives; x1..x8 where nothing writes the argument registers; the register a parameter arrives in when nothing but a return writes it in its range, `quiet_param`), temporaries in the others, stack slots for the rest, far-branch retry. Each block's scratch homes leave its instructions' most `need` registers of x0..x15 (`Live::scap`, which `assign` keeps per block as it does `jcap`): an instruction's general operands, a folded operand's own in its place, its result and two temporaries, at least 4, 8 for an aggregate or vector operation, assembly or a system operation, and the entry's first instruction the registers the parameters arrive in when homes may take x0..x8; `end_inst` checks it. The plan's registers (`plan_homes`; `seg_take`, `seg_bind`, `seg_block`, `seg_store`, `seg_edge`, `settle`): a block starts with the plan's registers of that block busy (`bmask`: no temporary takes one) and its listed values bound; a definition takes the plan's register, but one whose register an operand it still reads holds is made in a temporary and moved after the instruction (`settle`) unless its emitter reads its operands before it writes (`def_step`, `stepping`); a value made before its own instruction takes the register only when no value holds it, but one of the plan with no read left in the block, and nothing takes it in between (`early`); a temporary leaves a register the plan binds or an edge writes (`vacate_temp`, `vacate_live`); a value defined in its register is stored once after its definition when it keeps a stack home. A value keeps its zero-extended state (`Va.clean`) where the plan moves it (`Core::seg_in`: a register move keeps the bits, a narrow load zero-extends), so a narrow value in the plan's register is extended in place at its first unsigned reader in its defining block (`ext`), once for every reader after it. `next_reg`: a value whose one use is the next instruction, a conversion that keeps its bits (an extension, a truncation, a cast between a pointer and an integer, a reference's copy of a pointer) with a register home, is made in that home. Vectors of 8 or 16 bytes live in v registers, their slot written (`sync`) before an instruction whose code may branch past a lane (a masked access) reads it there; a masked access through a pointer of a vector in a register moves each active lane through a general register (INS, UMOV), lane 0 by LD1 or ST1 of the one lane at the pointer (`masked_in_reg`); a scalar into lane 0 of a vector of zeros is one FMOV (`vlane`, `zero_lanes`); a `compress_store` frees its length's temporary before it defines its count, so that it takes no more registers than `need` gives; a 16-byte vector that lives past its block, crosses no call and only lane-wise operations with a Neon form, loads, stores and edges use (`vec_homes`) takes a caller-saved v register home. `def_step`: a one-instruction result with no register of the plan, which dies in its block and which a back edge passes to a parameter, is defined in the parameter's register and owns it as a temporary. Two loads or stores at adjacent offsets through one address value pair into one `ldp` or `stp` in either offset order (`pair_next`, `pair`). The search crosses at most seven pure scalar instructions, never memory or control flow. The second load is defined early and may take its planned fixed home; a second store source must already exist. An already assigned second load home prevents pairing; an aggregate argument at a frame address loads its two 8-byte parts with one `ldp` through sp or fp (`frame_addr`). A register-passed aggregate parameter read only by entry-block loads of whole parts, before any instruction that may call, gives those loads its registers and takes no memory (`parts_taken`, `taken`; x64gen too). A product by 2^s + 1 is `add x, x, x, lsl s`, by 2^s - 1 a shift and a subtraction; a rotation (`lv::FOLD_ROT`) is `ror` (EXTR) by a constant or `rorv`, a left one by the negated amount; one of 8 or 16 bits (`rotate_narrow`) is the zero-extended value shifted both ways and joined by a constant, or by a register a 32-bit `rorv` of the register filled with the value's copies (their period divides 32); a high product of 32 bits or fewer takes `umull` or `smull` of the operands' W registers; a zero extension of a `clean` value reuses its register; a select's integer 0 is `xzr`, and its result takes the back-edge register (`def_step`). A `splat` is one `dup`. Homes: a leaf (no call but to a path that does not return, no system operation, variadic access or thread-local address) has 10 scratch homes from x0..x15 (`leaf`, `XSCR_LEAF`), not 6 from x9..x15; 6 when it holds a masked vector access that runs in general registers (`masked_gp`: `vmem_masked` takes five temporaries and three operands), an entry parameter keeping its arrival register (`take_home` `prefer`); an entry parameter that dies in the entry block keeps its register too. A loop header's parameter and the value its back edge passes share one register or slot (`back_share`, `shared`, `is_shared`; `edge_moves` skips a move to itself); a value spilled without a home takes the stack slot of the loop parameter it steps when it is that parameter's one reader (`step_slot`, `Live::slot_partner`), and the one of the two that ends last frees it, and a forward jump's argument is defined in its target parameter's register (`def_fwd`). An extern function's call under `no_plt` on ELF is `adrp/ldr/blr x16` through its GOT slot. For ELF (`Gen.elf`): TLS descriptors, a shared object's global symbols through the GOT, each frame's `.eh_frame` rules; for Mach-O its compact unwind encoding. Callee-saved registers are saved in whole pairs (x19/x20 to x27/x28, d8/d9 to d14/d15), each pair below the last with its lower register 8 bytes higher, the layout compact unwind's frame mode states; under the standard convention a variadic body saves x0..x7 and q0..q7 for its `va_list`. An unsigned or equality comparison with a constant whose negation modulo the width is below 4096 is `cmn` of that negation (`x != 0xFFFFFFFF` is `cmn w, #1`). A sum or difference with a constant of 12 bits shifted left by 12 is one instruction (`sub w, w, #0x200, lsl #12`). Narrow values (`lv::FOLD_TRUNC_ONCE`): a truncation to 8 or 16 bits that several comparisons read alone is made extended (`lv::Live::xtrunc`), and `ext` extends a value in its own register when its range ends in the block; never in a block whose later readers another path reaches, nor a parameter that arrived sign-extended. An intrinsic whose template writes its result into an argument's register takes the register `Live::assign` gives that argument when the result is the value the back edge passes to it (an accumulator: `call_over` fills `Live.cover`, `Live::over` gives the result the argument's register, `step_param` and `step_into` bind it), so a vector loop moves no accumulator; a `bsl` template writes its result over the operand that ends there (`select_over`, `select_form`: `bif` over the true one, `bit` over the false one), and a result made in a register of its own that starts a chain of such results to the back edge takes the parameter's register (`chain_home`); a float tree sum of at most 4 lanes reduces in registers (`reduce_reg`: EXT, FADD, FADDP) |

`driver::emit` sets `Package.native` for every linking build; a linking build for a target `nat::supported`
does not name fails ("no native backend for ..."), and an emission alone (`--emit-c`) writes C.
`native_header_facts` reads the constants of the
scoped C headers with the own preprocessor (in parallel, cached in `__sc_hfacts` by file size and
mtime; its first line names its format) under `--sysroot` or the discovered one, and the scalar class
of each `@layout` opaque type through its typedefs (`Package.opaque_cls`, `bindgen::scalar_class`).
Lowering gives such a type that LIR scalar type, not an aggregate: Microsoft x64 passes a one-field
struct of a `double` in an integer register, the `double` itself in xmm. A typedef of a struct or union
of scalars is `bindgen::SC_REC`: `bindgen::c_layout` computes its size, alignment and leaves from the
header's members (`Package.opaque_lay`), and lowering takes those leaves when the size and alignment
equal the declared `@layout` (a bitfield, a vector member, a `packed` or `aligned` attribute or a
`#pragma pack` leaves it unknown). Without a C environment for the target (no sysroot) a header has no
facts: its functions are the library's exports. The calling conventions classify an aggregate by its
layout leaves (scalars at offsets; an enum's tag and a capture by reference are leaves). A layout of 1
to 64 bytes whose leaves are unknown keeps none (`abi::unknown_class`), so the LIR stays complete; the
System V and AAPCS64 generators refuse a body whose signature or call passes one
(`CallLayout.unknown`), and the build fails with the refusal. Microsoft x64 passes an aggregate by its size alone. A dyn table a body's
lowering demands while it holds the lowering lowers when that body ends (`CEmit.dyn_due`). Float
arithmetic on two constants folds (`lir::eval::float_op`, also the interpreter's rule): a NaN result is
the first NaN operand quieted, else the positive quiet NaN, as LLVM folds it, since wasm leaves a new
NaN's sign to the host. A shared-library build sets `Package.pic`: x86-64 code then reaches every
global symbol through the GOT. A call moves its scalar register arguments, and a vector one register
takes whole, in one parallel move from where they are; a vector result one register returns stays
there. Windows thread-locals are native TLS (`.tls$`, SECREL), as clang and gcc 16 emit them.

An intrinsic with a row in its instruction set's table (`intrin::find`) is a plain LIR call; the
backend puts its arguments where its template expects them (`abi::intrinsic_layout`: vectors and floats
in v0/xmm0 and on, integers in x0.. or rdi, rsi, rdx, rcx, r8, r9, r10, r11, the result in v0/xmm0 or
x0/rax; on wasm the operand stack, through locals when the template reads its arguments in another
order) and expands the template in place of the call, its constant arguments substituted (a
non-constant one where the template needs an immediate refuses the body). An integer argument whose
register the template does not name is such an immediate (`CallLayout::imm_arg`): no register takes
it, and an intrinsic that names no general register writes vector registers alone (on x86-64 it is no
call for the general homes and counts as a register operation, `Gen.vreg`). A vector argument or
result one register holds stays in it (`CallLayout::whole_vreg`: 8 or 16 bytes, and on x86-64 the
register bytes of the body, `CallLayout.wide`, so a body of 32- or 64-byte registers computes its
`_mm256_`/`_mm512_` templates in ymm/zmm registers). An arm64 store template (`st*`) reads its vector
where it is (`intrin::vwrites`). An x86-64 template that names its general registers only as 64-bit
addresses (`intrin::gp_addresses`: inside parentheses, and no mnemonic that writes a register it does
not name) reads each such argument from the register that holds it, else from a temporary
(`intrin::grename`, `Gen::gp_renamed`); it writes no general register, so it is no call for the
general homes either. Any other expansion clobbers what a call does; on Windows the values in rdi and rsi that the template names, which Microsoft x64 saves, go to slots around it.
`native_header_facts` reads the headers under the target's sysroot (`Package.sysroot`, from
`--sysroot=`, else discovered by `bindgen::ctarget`).

A module the backend cannot compile (module-level assembly the target's assembler does not take, a
body the lowering or the backend refuses, a call of a header's `static` function or of an intrinsic
without a template) is a build error that names the module and why (`native_plan`); `SC_NATIVE_STATS`
reports each module. Each native module gives `m.o` (its own items, reused by the emission cache) and
`m__inst.o` (the rest). A function of the module outside the seed set (`fn_pred`), emitted because a text
named it, is in the rest: the set keys the emission cache, and a later build may not name it. The record `__sc_native` holds, per module, the key its own part was compiled
under (its emission cache key xor `nat_base`, which mixes in the build configuration, the CPU
features, the LIR optimizer's switches, the header facts and, with debug information, the compile
directory), its low bit `NAT_OBJ`
when that part has an object; `nat_trust` turns an emission cache hit into a miss when the record does
not hold the module under the current key. An edit inside a body that only calls read (not generic, not
a `const fn`, not an interface member) misses only its own module and the modules whose sections read what changed of the function
(output-layout.md, Validation).

Every other object (an instance part, or the own part of a module the emission cache missed) is reused
when its input is the input of the object at its path: `nat_piece_key` hashes, in 128 bits, the
build configuration (`nat_base`), the compiler, the module-level assembly, the object's functions and
data with every table of their bodies and definitions, the definitions it copies (a symbol no unit
claims, `ob::copy_flags`) and what those name in turn, and of each symbol named what the generators
read of a reference (`nat_sym_ref`: spelling, kind, linkage, C-library and kept marks, section; whether
a function has a definition only where its spelling may name a C function), a named data symbol's
definition, files and messages by spelling (`lines[0]`, "no location", aside: no row names it), and on
wasm the package's files and each named function's signature body (no key when a function has none:
the generator then reads any call of it). The record `__sc_native_keys` holds each object's key with the
hash of its bytes (`nat_bytes_hash`), by path below the tree: a reused object is read and its bytes
checked against the hash (they then go to the link from memory), so an object another writer replaced is
compiled again. A build removes the record before it writes objects and writes it after.
`SC_NATIVE_STATS` reports the reused count. A record field the generators read that the key does not
hash is a stale object: the `static_assert`s on the record sizes beside `nat_piece_key` fail when a
record gains a field.

Debug information follows the profile's `debug` key (`loader::Package.debug_info`), which sets
`lir::ir::Package.debug` and its `comp_dir` (the compiler's working directory). Each
generator records a row per change of LIR location at the instruction's code offset (x86-64 maps them
through jump relaxation), the prologue taking the first row's location; `codegen::dwarf` writes them.
The code and data sections are the same bytes with and without it (`tests/codegen/debug_info_test.spc`).

A native build renders no C body (`cemit::backends_of`: no `BK_C` for any module; `emit_body_core`
returns at once); the declarations still render, and so does every body of the vector backend entries'
emitter (`CEmit.render_all`: a header's `static inline` C, no object's). Where a body renders no C, its
lowering journals for the TU cache what it demands (`rec_on` stays on: statics through `lir_stat_need`,
type descriptors through `CEmit::ti_need`), which the renderer journals otherwise. The registry is a
native object too (`__sc_registry_n.o`); `__sc_registry.c` is still written, and no C compiles it.
The vector bounds-check helpers live in `std/rt/lanes.spc`, loaded only when a
program names a vector type.

`check_all` (in `lir_stage`, under `SC_LIR`) verifies every body the build lowered (the
per-TU cache keys on `SC_LIR`, so a replayed module passed it before), and under `SC_LIR_EVAL` in a
test build runs each test without fixture arguments in the evaluator, the tests spread over
`--jobs` workers with an evaluator each: against the CTFE run (`lw::probe_tests`, before the body
syntax is released, 1<<18 steps; trap kind and location must match), or, where CTFE stops at a
construct it does not support, against the test's expectation (it passes, or with `should_panic` it
traps). A test that calls FFI (CTFE's `Interp.ffi`, or the evaluator's `EV_FFI`) or passes a budget
(CTFE's, or the evaluator's 1<<21 steps) is not compared. The test build then ends: `run_package`
returns after the emission, and `manifest_test` builds no project binary and runs no test.
